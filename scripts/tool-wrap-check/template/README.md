# loghub-tool-wrap-check

Verification project for the Log Hub hook's **CLI tool wrapper** (Tools/MCP tab, task T-26). It
checks that a monitored tool behaves exactly the same with and without the wrapper — same stdout
and stderr bytes, same exit code — and that the wrapper steps aside when anything goes wrong.

Generated by `scripts/tool-wrap-check/create-check-project.mjs` in the Log Hub repo (path in
`check.config.json`). Re-running that script refreshes the generated files; it never deletes
anything. The rows and their expected results are documented in the repo's
`docs/knowledgebase/algorithms/tool-wrapper-fidelity.md`.

## Contents

| Path | What |
|---|---|
| `bin/` | Fixture tools: `zz` (20 000 lines, exit code from `$ZZ_EXIT`, `zz args …`), `zzbin` (bytes 0–255), `zzin` (stdin to stdout and stderr), `zzsleep` (sleeps), `zzc.cmd` (Windows) |
| `run-check.mjs` | The runner (below) |
| `check.config.json` | Paths of the Log Hub repo, its hook and the Claude profile for the live run |
| `linux/Dockerfile` | Linux image for `check:linux` (`node:22-bookworm`) |
| `linux/live-settings.json` | Hook registrations for the live session (`claude --settings`) |
| `runs/<timestamp>-<kind>/` | One folder per run: shims, records, `fidelity-results.json`, `live.json` |
| `.loghub-tool-wrap-check` | Marker: the generator only writes into a folder that has it (or an empty one) |

## How to run

```sh
npm run check                                   # this machine: Git Bash, PowerShell 5.1, PowerShell 7 (when installed)
npm run check:linux                             # Linux container, node:22-bookworm (GNU tools)
npm run check:linux -- --image node:22-alpine   # Linux container, busybox tools
npm run check:linux-live                        # live `claude -p` session in log-hub-dev:latest
```

- `check` / `check:linux` run the repo's `hook/.claude/telemetry_tool/__tests__/tool-wrap-fidelity.algo.test.js`
  with `LOGHUB_FIDELITY_TEST=1`. In the container the repo is mounted read-only at `/repo` and
  this project read-write at `/work`; the container is started with `--rm` (only the container is
  removed, never a host file). Without Docker the Linux runs print one message and exit 2.
- `check:linux-live` uses the shared sandbox profile (`docker-dev/claude-home` of the repo, or
  `--claude-home DIR`), mounted read-write because Claude refreshes its token; the profile is
  never copied or changed by these scripts. It seeds `.artisyn/ai_work_dir/tool-wrap/config-cache.json`
  with `zz`, `ls` and `find`, asks Claude to run `zz | head -1`, `ls /nonexistent` and
  `find /nonexistent`, and checks the wrapper's records: `zz` with `consumerClosed: true`, `ls`
  with a non-zero exit code. `find` is reported for information only: Claude Code's Bash tool
  defines `find` and `grep` as shell functions (its embedded bfs / ugrep), and a shell function
  always wins over a PATH shim, so those two are seen through the transcript only (`no wrapper`).
  It spends a small amount of real Claude credits.

## Reading the results

- Each fidelity row prints `pass`, `fail` (with the first line of the reason) or `skipped` (the
  row's OS or shell is not available here). The full detail is in
  `runs/<timestamp>-<kind>/fidelity-results.json`; the shims and records of every row are in the
  row's folder next to it.
- `wrapper overhead` is the median wall time of `find /nonexistent` with and without the wrapper.
- The live run prints one line per check and writes `runs/<timestamp>-live/live.json`.
- Exit code: 0 = all passed, 1 = a failure, 2 = the environment is missing.

Old `runs/` folders are never removed automatically — delete them by hand when no longer needed.
