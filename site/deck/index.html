You already know what AI coding costs — per month, per day, per session — and controlling that is right and useful. But a number alone is not an answer: this session cost {{ds:session.total|usd0}}. Is that a lot or a little, good or bad? How do you make it cheaper — or when is it worth spending more for better quality? Log Hub answers the next questions: why it costs that much, which factors drive it, whether your harness works the way you designed it, and what your tools really bring — for one session and across the team. The example: a team of {{ds:team.developers}} developers, {{ds:daily.sessions}} sessions a day, {{ds:team.workingDays}} working days — {{ds:monthly.total|usd}} a month. All figures are fictional.

{{site:url}}

You decide where the data flows. On one machine the shipped docker-compose.yml publishes the app on 127.0.0.1:5003 only and sessions go to a Postgres container on the same host. For a team the same setup runs on your LAN or behind your VPN with your own TLS proxy; developers' hooks upload to that server and nowhere else. DataArt runs no hosted service and receives nothing. Sign-in: identify by email, passwords (with optional email confirmation) or Azure Entra ID single tenant. Log Hub works fully in an air-gapped network: the app, its in-app help and every user document ship with the product. The only outbound requests are two public GETs at most once a day — the Anthropic price list and the Claude Code version list on npm — which send no data; MODEL_PRICING_FETCH_ENABLED=false and AI_TOOL_VERSION_CHECK_ENABLED=false turn them off for an air-gapped install. Self-hosted: Docker and Postgres, a one-command install; your data stays in-house. The hook installs into a repository via npx and captures the full session transcript by design — see Data collection in the docs. Backward compatible: a new server keeps accepting uploads from older hooks. Sessions can be exported and imported between Log Hub installations.

What is collected, who reads it, how long it stays.

  • Full transcripts, unredacted by design — control the source with Claude Code deny rules.
  • Managers see analytics without prompt text; admins see no session data.

Ships with a security hardening guide, a known-limitations table and a RACI responsibility matrix. The hook only observes — it never blocks a tool call.

{{site:url}}

The hook uploads the full Claude Code transcript, unredacted by design: prompts, tool results, file contents Claude read and command output — if Claude saw a secret, it is in the transcript. Keep files out at the source with Claude Code permissions.deny rules. It also collects CLAUDE.md, rules, skills and MCP configuration (credentials stripped), the git remote (credentials stripped), branch and git user. Access: in a restricted team (the default) members see only their own sessions, the owner and ADLC trainers see prompts, managers see analytics without prompt text; a transparent team is opt-in; the admin role grants no access to session data. A member is visible to the team only after accepting a disclosure notice. Retention: SESSION_RETENTION_DAYS (default 30), deletion is a hard delete. No encryption at rest in the app — use volume encryption; TLS at your proxy. Documented in Data Collection, Trust model and Security Hardening (with a known-limitations table) and the RACI responsibility matrix.
