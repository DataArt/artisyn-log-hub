# Golden sessions

Hand-checked Claude Code sessions with known numbers (cost, tokens, work time, lines, change
surface). Scenario specs upload them through the public API and compare what the app shows with
`expected.json`. Design: `docs/qaa-overview/scenarios/03-session-view-reports-golden.md` §2; plan
decisions DD D1–D3 in the task's `impl-plan.md`.

None of these is a copy of a real session. Identities, hosts and paths are synthetic: the e-mail
domain is `arrakis.test`, POSIX paths live under `/work/repo-gold`, Windows paths under
`C:\work\acme-shop`.

## Layout of a fixture

| File | What it is |
|---|---|
| `session.jsonl` | the root's Claude Code transcript (`type=claude`) |
| `artisyn.jsonl` | the hook's own lines for the root (`type=artisyn`): `SessionStart` (with `git`) at the transcript's first timestamp, `prompt_start` with `git` per prompt, `SessionEnd` at the transcript's last timestamp, plus the harness self-report where the fixture needs it. The lifecycle lines matter: the session's start/end come from this log, and the work-time report clamps each session to its end |
| `subagents/<agent-id>.jsonl` | sub-agent transcripts (`type=claude-subagent`); workflow agents under `subagents/workflows/<wf>/` |
| `upload.json` | upload manifest: roots, their files and every sub-agent's `sessionId`, `parentSessionId` and `workflowRunId` |
| `expected.json` | the numbers a test asserts (DD D3), per root: branch, week, start/end, work time, cost (tree and own), tokens per node, cache ratios, tools, lines, change surface, plus fixture-specific rows from `scenarios/03` §2.3 |
| `README.md` | what the fixture checks |

## Placeholders and dates

- `{{RUN}}` — run id, part of every session and agent id, so one stand can hold several uploads of
  the same fixture.
- `{{REPO}}` — the repository URL in the artisyn `git.repo` field.
- Timestamps are real ISO strings anchored at `A` = Monday 2026-01-05 (W1 = 5–11 Jan, W2 = 12–18 Jan).
  The loader shifts all of them by whole days so that `A` becomes the Monday two weeks before the
  current week, keeping every session in the past and inside a "last 30 days" range.

## Loading

`tests/scenarios/helpers/golden.ts`:

```ts
const key = await createApiKey(user.api);
const runId = goldenRunId();
for (const id of GOLDEN_FIXTURE_IDS) {
  await uploadGolden(api, key.key, id, { runId, queue: { db, userId: user.id } });
}
const expected = loadExpected('gs-04');
```

Every file goes through `POST /api/v2/logs` with `X-API-Key`, exactly as the hook sends it, and the
call returns once `upload_queue` is idle for the user.

## Checking the numbers

`repo-gold.expected.json` holds the REPO-GOLD totals (`scenarios/03` §2.4).

```sh
node tests/golden/check-arithmetic.mjs   # re-derive every literal from the transcripts and the DD D3 rates
```

It parses the transcripts itself, prices them, recomputes ratios, concentration and every
repository total, and exits 1 on any mismatch; `npm run test:scripts` runs it through
`scripts/__tests__/golden-arithmetic.test.js`. The app side is
`tests/scenarios/view/golden-load.spec.ts` (`npm run test:scenarios -- --mode a --grep GOLDEN-LOAD`).
When the app disagrees: a code bug keeps the correct literal and marks the test `test.fail` with a
pointer to the task Notes; a design mistake is fixed here, in the literal (and its README).

## Regenerating GS-09

```sh
node tests/golden/gen-gs09.mjs          # rewrite gs-09-windows-paths/ and print its shape
node tests/golden/gen-gs09.mjs --check  # fail if the committed files are stale
```

The generator has no randomness; edit it, never the generated JSONL.
