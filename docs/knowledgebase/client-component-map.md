## `client/src/viewer/`

```
app.css                         Global viewer styles
```

### `viewer/hooks/`
```
useHashRoute.ts                 Route path-builder — exports the `routes` object used with react-router-dom's `useNavigate()`; does not parse window.location.hash (actual routing is `createHashRouter` in `main.tsx`)
useModelPricing.ts              Fetches and caches model pricing from the API
useAdminModelPricing.ts         (2026-10-13) Admin model-pricing hooks. `useAdminModelPricing()` = useQuery over GET /api/v1/admin/model-pricing (key `ADMIN_MODEL_PRICING_QUERY_KEY` = ['admin','model-pricing']). `useModelPricingMutations()` = four mutations (setAdminModelPrice, setAdminModelOverride, clearAdminModelOverride, importOpenRouterPricing from api.ts), each invalidating both ['admin','model-pricing'] and the public ['model-pricing'] key so session costs re-price after an edit
useAiToolVersions.ts            (2026-09-23) useQuery over GET /api/v1/ai-tool-versions/claude-code (key ['ai-tool-versions','claude-code'], staleTime 5 min, modelled on useModelPricing); returns the ascending `history` array or `undefined` while loading/on error. Called by `SessionDetailPane.tsx`, which passes it to `SessionSummaryTab` as the optional `claudeReleaseHistory` prop for the `claude-version` detector
useDraggableWidth.ts            Drag-resizable panel width with localStorage persistence; `onMouseDown` returns a drag handler for a resize handle element; `rightPanel: true` for a panel right of its handle (dragging left widens it)
useDragScroll.ts                Click-and-drag panning for a scrollable container; returns `{ ref, isDragging, onMouseDown }`; 4px movement threshold preserves child clicks. Used by AgentTree horizontal scroll
useDebounce.ts                  Debounces a value (admin table filters)
useCopyToClipboard.ts           Copy text to clipboard with visual feedback (Install tab, tool views); `useCopyToClipboard(text, resetMs = 1500)` — the Bash view's "Copy original" passes 2000
useKeepAlive.ts                 Sends GET /api/v1/ping every 60 s while user is authenticated; clears on logout
useBuildVersion.ts               Fetches the public (no-auth) GET /health/version endpoint (server/src/health/health.controller.ts), staleTime Infinity; returns { version, gitCommit } — 'dev'/'unknown' outside a Docker build; used by MainNav.tsx to label the running build in the header
useAuthConfig.ts                 useQuery wrapper around GET /api/v1/auth/config (public, no-auth), staleTime Infinity; returns { mode, azure?, adminContactEmail?, passwordResetAvailable? } used by LoginPage.tsx (mode-aware form + Forgot-password link state), ForgotPasswordPage.tsx (passwordResetAvailable === false disables the form), SignupPage.tsx (adminContactEmail on email_delivery:'failed'), and MainNav.tsx ('none' mode swaps Logout→"Edit email")
useCooldown.ts                   `{ secondsLeft, start(seconds) }` countdown hook mirroring the server's 60s resend cooldown; `start()` reseeds from a 429's Retry-After. Used by SignupPage.tsx's resend button and PendingRegistrationsTable.tsx's per-row Resend
useDataCollectionConsent.ts       Returns 'required' | 'accepted' for the data-collection notice. Purely derived from the ['user-settings'] and ['consent-notice'] caches that main.tsx's Bootstrap prefetches — it never fetches, so AppLayout decides synchronously and neither the app nor the consent screen ever flashes. Compares parseConsent(stored) against noticeHash(noticeText): absent, mismatched or unparseable ⇒ 'required'; an unreadable notice ⇒ 'accepted' (a failed asset fetch must not lock anyone out)
useNewUserNudge.ts               `useIsNewUser()` — true only once both ['my-repos'] and ['teams'] (the keys AppLeftNav already mounts, so no extra request) have loaded empty. `useNewUserNudge()` navigates such a user to routes.apiKeys once per browser session (sessionStorage key `artisyn:newUserNudgeDone`) and only from routes.main, so an explicit deep link is never overridden. Called from main.tsx's AuthedApp — i.e. only after consent
lib/consent-queries.ts             The three queries the consent gate reads (user-settings, consent-notice, retention-days), defined once with staleTime: Infinity so Bootstrap's prefetch counts as fresh at mount and no observer refetches. Bootstrap, useDataCollectionConsent and DataCollectionConsentScreen must all use these exact objects — a drifting key or a missing queryFn makes the gate fetch at render time (and React Query logs a console error, which several e2e specs assert against)
```

### `viewer/help/`
```
HelpModal.tsx                   Dialog-based help modal: left nav + article pane; fetches /help/<slug>.md at runtime and renders it with remark-gfm + rehype-slug (heading ids). Opens on DEFAULT_HELP_SLUG = 'getting-started'; keeps `pendingAnchor` and, after the article renders, scrolls to that id or to the top. Articles flagged `downloadable` get a "Download .md" button (plain same-origin <a download> to /help/<slug>.md, file name from helpDownloadFileName())
HelpMarkdownLink.tsx            The `a` renderer passed to ReactMarkdown: #anchor → scroll inside the pane; <slug>.md[#anchor] → onNavigate(slug, anchor); unknown slug → console.warn, no navigation; http(s)/mailto → new tab + trailing ↗
help-links.ts                   Pure parseHelpHref(href, knownSlugs) → external | anchor | page | unknown (the link rules of scripts/user-docs/links.js minus `source` basenames, which the generator already rewrote)
articles/index.ts               helpNav = the repo-root user-docs/nav.json (imported via the @loghub/user-docs alias; sections, article slugs, optional `downloadable` and `source`) + helpDownloadFileName(slug) → artisyn-log-hub-<slug>.md
```

### `viewer/components/`
```
LazyFallback.tsx                Shared Suspense fallback for lazy-loaded routes/tabs — centered Loader2 spinner; `fullScreen` prop switches between a full-viewport container (route-level, mirrors main.tsx's Bootstrap loading screen) and an `h-full` one (in-page tab-level)
DataCollectionConsentScreen.tsx The first-run data-collection notice. Rendered by main.tsx's AppLayout *instead of* `<AppShell><Outlet/></AppShell>` while useDataCollectionConsent() says 'required' — not a Dialog and not an overlay, so no nav, no page content and no shell query exists behind it, and a deep link cannot get past it. Renders /help/data-collection-notice.md via ReactMarkdown+remarkGfm with `{{RETENTION_DAYS}}` substituted from the ['retention-days'] cache; the "If the assistant handles secrets" section is split out of the markdown flow into an amber AlertTriangle block. Exactly one control: "I understand and accept" → saveUserSetting(DATA_COLLECTION_NOTICE_SETTING, encodeConsent(hash)) then invalidates ['user-settings']. No ×, no Escape, no decline; on failure the error shows under the button and the screen stays
```

### `pages/login/`
```
LoginPage.tsx                   Mode-aware — fetches useAuthConfig() before rendering any form; branches on config.mode: 'none' → IdentifyForm (single email field, POST identify); 'password' / 'password-confirm' → PasswordLoginForm, whose "Forgot password?" link takes forgotPasswordLinkState(config) (forgot-password-link.ts): active → navigates to /forgot-password; disabled → same button with disabled + cursor-not-allowed opacity-60 no-underline, aria-describedby="forgot-password-hint" and a right-aligned text-xs muted hint SMTP_NOT_CONFIGURED_HINT below it; hidden → not rendered; 'password-confirm' also shows a distinct "please confirm your email first" message on 403 email_not_confirmed; 'azure-oauth' → AzureSignInButton only. Config-fetch failure renders a generic "temporary issue" message with no email address. Also shows a "Sign in with Microsoft failed" banner when ?oauthError=1 is present.
forgot-password-link.ts         Pure helper (no React): forgotPasswordLinkState(config) → 'active' | 'disabled' | 'hidden' (passwordResetAvailable true → active, false → disabled, absent i.e. older server → active in 'password-confirm', hidden in 'password'); exports the ForgotPasswordLinkState type and SMTP_NOT_CONFIGURED_HINT = 'SMTP server is not configured', shared by LoginPage.tsx and ForgotPasswordPage.tsx
AzureSignInButton.tsx           Mode 4's single button — full page navigation (window.location.href, not react-router) to GET /api/v1/auth/azure since the OAuth exchange is entirely server-side
```

### `pages/confirm-email/`
```
ConfirmEmailPage.tsx            Reads ?token= via useSearchParams; calls confirmEmail(token) on mount; renders success/invalid/expired(410)/already-confirmed(409) states
```

### `pages/signup/`
```
SignupPage.tsx                  Account creation form — password strength is server-policy-driven (no client-side length check beyond the 128-char hard cap; weak_password server error surfaces inline). On success: email_delivery undefined → logs straight in (Mode 2); 'sent' → "Check your email to confirm your account" panel with a Resend button (useCooldown, 60s, seeded from a 429's Retry-After); 'failed' → admin-contact message using useAuthConfig()'s adminContactEmail
```

### `pages/forgot-password/`
```
ForgotPasswordPage.tsx          Email form -> POST forgot-password -> generic confirmation message (forgotPassword() returns { email_delivery } but the page still shows the same enumeration-safe message regardless). When useAuthConfig().data?.passwordResetAvailable === false (Mode 2 without SMTP) it renders the SMTP_NOT_CONFIGURED_HINT note (role="note") above the input and disables the email input and "Send reset link" button; "Back to log in" stays active. While the config loads or fails the form stays enabled
```

### `pages/reset-password/`
```
ResetPasswordPage.tsx           Reads ?token= via useSearchParams; new-password + confirm form -> POST reset-password. No client-side length minimum (server policy-driven); distinguishes weak_password/password_mismatch error codes from an invalid/expired/used-token error
```

### `pages/main/`
```
MainPage.tsx                    Landing placeholder ("Select an item from the left panel")
MainNav.tsx                     Top bar — logo, title (+ small gray build label via useBuildVersion.ts: the 7-char git commit, full hash as tooltip; the package version only when no commit is baked in, i.e. `dev` locally — the version is not bumped per release, so it is never shown for a real build), NotificationBell, user email, logout, `components/teams/AccessModeBadge.tsx` (renders only on the two team routes), Help button (opens HelpModal). ### `pages/repository/`
```
```
RepositoryView.tsx              Repository page orchestrator — thin shell that wires useRepositoryViewState + useRepositoryData; owns viewMode, branchSelectedSession, delete dialog/mutation state, and the PageTabs layout (Sessions / Analytics / Reports / Tools/MCP / OKF / Settings — `tools/RepoToolsTab.tsx` and `okf/RepoOkfTab.tsx` lazy-loaded); passes the transient `tu` deep-link param (`targetToolUseId` / `clearTargetToolUse` from useRepositoryViewState) down to the Sessions panel; derives `filterByUserEmail` ONCE (`teamId === undefined && !showAllUsers ? user?.email : undefined`) and feeds both the session list and useNewSessionPoll from it — the two previously each re-derived the same ternary and could drift; also instantiates useOpenBranches (branch expand/collapse state) and useNewSessionPoll (background poll → `hasNewSessions`), rendering a `NotificationDot` badge next to the refresh button (`leftActions`, tab-independent) when true; the refresh button also calls `useSessionListRefreshing(repoId, teamId)` and, while `true`, switches to `bg-indigo-50 border-blue-600 text-blue-600` with the `RefreshCw` icon spinning (`animate-spin`) — independent of the `NotificationDot` signal, both can show at once
RepositoryHeader.tsx            Repo info bar — URL, session count, user count, per-context key/value badges (the "Private repo view" badge was removed by 2026-10-21-private-repo-visibility)
RepositorySessionsPanel.tsx     Sessions tab content — drag-resizable session list (SessionListPanel) + SessionDetailPane; owns the draggable width via useDraggableWidth. Renders `<SessionDetailPane key={selectedSession.sessionId}>` so a session change remounts the pane (per-tab state resets for free), `SessionNotFoundState` when the URL `session` matches no listed session once the sessions query settled, and the "Select a session…" placeholder when there is no `session` param
SessionNotFoundState.tsx        Not-found pane for a URL `session` that is deleted or not accessible — centred `⌀` glyph, "Session not found" title, one muted line and an outline Close button (`onClose` removes `session` + `tab` with `replace: true`); same empty-state styling as the "Select a session…" placeholder; `data-testid="session-not-found"`
useRepositoryViewState.ts       Hook — manages URL-derived tab/param state (mainTab, sessionTab, topN, sessionId, `showAllUsers` via `users=all`), session/analytics navigation, repo URL resolution (`repoDetailQuery.data?.repoUrl` — `fetchRepositoryDetail(repoId, teamId)`, key `['repo-detail', repoId, teamId ?? null]`), and query invalidation on repo change. `handleSessionSelect` pushes a history entry (no `replace`); the tab/top-N/users setters replace. `showAllUsers` lifts the personal-repo email filter and lives in the URL rather than localStorage (unlike `hideHookSessions`, a lasting per-repo preference) — it is a transient, shareable reveal that should reset on the next navigation. Also reads the transient `tu` param (`targetToolUseId`, the Tools/MCP "Open in session" deep link) and clears it with `clearTargetToolUse` (`replace: true`) once the Logs tab has resolved it; session/tab changes drop it too. `setMainTab` drops the Tools/MCP tab's `t*` params (`TOOLS_PARAM_KEYS`) when leaving that tab
useRepositoryData.ts            Hook — all data fetching for RepositoryView: sessions, summary, contexts, detail, logs queries; favorite mutation; parsedLogs and subagentLogsMap derived state. Also auto-refreshes the open session's logs: a sibling `session-watermark-poll` query (own key, distinct from `repo-sessions`/`repo-sessions-branch` — same sibling-poll pattern as `useNewSessionPoll.ts`, so it never trips `useSessionListRefreshing`'s banner) polls the selected session's `endTime` on `SESSION_POLL_INTERVAL_MS`; a mismatch against the endTime last seen when `session-logs` was fetched invalidates that query — silently if the session stayed selected, or via the explicit `isReloadingUpdatedSession` flag (consumed by `SessionDetailPane.tsx`'s banner) if the user just switched into a session whose cache was stale
useOpenBranches.ts               Hook — controlled open/closed state for branch-view accordions; stores only explicit user-toggle overrides in a `Map<branchKey, boolean>`, `isBranchOpen(key, index)`/`toggleBranch(key, index)` default to "first branch open" (`override ?? index === 0`) when untouched; owned by RepositoryView, passed down through RepositorySessionsPanel/SessionListPanel to BranchSection (controlled `isOpen`/`onToggle` props) and consumed directly by useNewSessionPoll to gate per-branch polling
useNewSessionPoll.ts             Hook — background "new sessions" detection for the refresh-button badge; runs sibling poll queries (`repo-sessions-ids-poll` / `repo-sessions-branch-ids-poll`, own `refetchInterval` from `SESSION_POLL_INTERVAL_MS`) against the lightweight `fetchRepositorySessionIds()` (`GET /sessions/ids`, bare `string[]`, `hideHookSessions`/`filterByUserEmail` filtering done server-side) alongside the existing full-payload display queries, and diffs ids via pure exported `diffNewSessionIds(polled: string[], displayedIds)`; the displayed side is still filtered client-side through `filterVisibleSessions` (poll side arrives pre-filtered); branch mode only polls currently-open branches (via `isBranchOpen` from useOpenBranches); returns `hasNewSessions: boolean`
useSessionListRefresh.ts        Hook — `useSessionListRefreshing(repoId, teamId)` wraps `useIsFetching` with a predicate matching `repo-sessions`/`repo-branches`/`repo-sessions-branch` queries for this repo/team that already have data (`query.state.data !== undefined`), so it fires only on a refetch of already-loaded data, never the initial load; returns `count > 0`. Also exports the pure `didRefreshJustFail(prevError, nextError, hasData)` helper (falsy→truthy error transition while `hasData` is true) used by SessionListPanel's refresh-failure toast. Consumed independently by RepositoryView.tsx (refresh-button spin state) and SessionListPanel.tsx (refresh banner) — both already have repoId/teamId in scope
RepositorySettings.tsx          Repository settings panel — thin tab shell wiring seven URL-backed sub-tabs (`stab` param via `useRepositorySettingsTabState.ts`; distinct from the session-detail `tab` param and RepositoryView's `mtab` param): "Display" (hide-hook-sessions checkbox, inline), "File Categories" (delegates to `FileCategoriesEditor.tsx`'s `ConfigEditor`), "Analysis" (delegates to `AnalysisSettings.tsx`'s `CacheCreationThresholdSetting`/`TurnEndCostAdvisorSetting`, each saved read-modify-write into the same `RepoConfig` blob as the file categories via `withSavedAnalysisSettings()`, so no save path clobbers another), "Monitored Tools" (delegates to `tools/MonitoredToolsSettings.tsx`, which loads and saves its own tool-monitoring config), "Session Attributes" (delegates to `SessionAttributionSettings.tsx`; genuinely team-only, so unlike every other tab it always saves via `putTeamConfig` through its own dedicated `sessionAttributionMutation` regardless of whether the panel is open in team view or personal view — gated by `data.teamId`/`data.canEditTeamConfig`, which resolve independently of the `teamId` route prop), and two owner-gated (`!readOnly`) tabs that delegate to their own extracted components — "Maintenance" (`MaintenanceSection.tsx`) and "Import/Export" (`export-import/ImportExportSection.tsx` — hosts session zip export/import plus the Session Statistics Export mode, formerly its own top-level tab). Also owns the settings query/mutation (team/user config load+save) and passes derived `rows`/`currentConfig`/`readOnly` down to `FileCategoriesEditor.tsx`.
FileCategoriesEditor.tsx        File-category editor extracted from RepositorySettings.tsx (component-size split) — exports `ConfigEditor` (drag-to-reorder row list, validation, save/reset with confirm) plus `CategoryRowEditor`/`FileTester`/`RegexpCheatSheet` (internal) and the `CategoryRow`/`configToRows`/`rowsToConfig`/`newRowId` helpers shared with RepositorySettings.tsx
AnalysisSettings.tsx            "Analysis" tab body, extracted from RepositorySettings.tsx (component-size split) — exports `CacheCreationThresholdSetting` (`highCacheCreationThreshold` number input bounded by `viewer/lib/cache-ratio-ui.ts`) and `TurnEndCostAdvisorSetting` (just the enabled toggle — there is no `minSessionCostUsd` input, since the gate does not enforce it; the stored value still round-trips unchanged via `RepositorySettings.tsx`'s `saveTurnEndCostAdvisor()` for un-upgraded-hook back-compat, it is just no longer editable here); both are plain controlled inputs with their own local "has this changed from `initialValue`" save-gating, no data fetching of their own
SessionAttributionSettings.tsx  "Session Attributes" tab body — attribute list editor: drag-to-reorder rows (key/label/type/prompt via a native `<select>` + `<textarea>`, mirrors `FileCategoriesEditor.tsx`'s row-list shape), add/remove, client-side validation mirroring the server's `validateConfig()` branch (`viewer/lib/session-attribution-ui.ts`: key regex, 12-attribute cap, label/prompt length caps, duplicate-key detection), an always-on/off "AI Attribute Extraction" checkbox, and an always-visible 1–5¢-per-evaluation cost note. `key`/`type` are locked (`keyLocked` prop, driven by a `savedKeys` list from the parent) on any row that was already persisted — the immutable key/type binding is enforced client-side to avoid a save-time 400, not just server-side. Renders a "this repository has no team" message instead of the form when `noTeam` is true, or "Managed by team owner" above a read-only render when `readOnly` is true. Exports `AttributeRow`/`attributesToRows`/`rowsToAttributes`/`newAttributeRowId`/`SessionAttributionValue` for RepositorySettings.tsx
SessionExportSection.tsx        "Session Statistics Export" section — period ToggleGroup week/month/Custom via DateRangePicker, team-view-only "User" select from `fetchTeamMembers`, Export button wiring `session-export-runner.ts` + `SessionExportProgressModal.tsx`; no longer its own RepositorySettings.tsx tab — rendered as the "Export Session statistics" mode inside `export-import/ImportExportSection.tsx`
MaintenanceSection.tsx          "Maintenance" section, extracted from RepositorySettings.tsx (component-size split) — a "Recompute all sessions" button calling `recomputeAllSessions()`, with a loading state and a brief success/error message
```

## Key rules for navigating this structure

| You want to… | Look in… |
|---|---|
| Change the left sidebar or top nav | `components/AppShell.tsx`, `components/AppLeftNav.tsx`, `components/top-nav/` |
| Change admin panel pages | `pages/admin/` |
| Change session list/detail layout | `pages/repository/RepositoryView.tsx` |
| Change the session log view | `pages/repository/session-log/` |
| Change what "changed files / folders / concentration" shows | `pages/repository/session-log/change-surface/` (tab), `session-log/summary/detectors/change-surface-*.ts` (findings), `analytics/ChangeSurfaceBarChart.tsx` (chart), `reports/ChangeSurfaceReport.tsx` (report), `lib/change-surface-ui.ts` (bands) — and read `docs/knowledgebase/change-surface.md` first |
| Change the OKF (knowledge-base use) tabs | `pages/repository/session-log/okf/` (session tab, shared verdict card / bundle cards / tree), `pages/repository/okf/` (repo tab), `lib/okf/okf-verdict-text.ts` (texts) — and read `docs/knowledgebase/okf-usage.md` first |
| Change the Tools/MCP tab (MCP / monitored CLI tool calls) | `pages/repository/tools/` (tab, tree, calls table, details, Monitored Tools settings tab), `models/tool-monitoring.ts` (types), the `tool-monitoring` fetchers in `viewer/api.ts`, `packages/tool-monitor/` (name rules shared with the server) — and read `docs/knowledgebase/tool-monitoring.md` first |
| Change the Bash command view's analysis or layout | `packages/bash-view/src/` (`@loghub/bash-view`, shared with the server); the client loader is `lib/bash-view/` |
| Change chart or analytics | `pages/repository/session-log/charts/` (native session charts), `pages/repository/analytics/` (D3 repository analytics) |
| Change anything about team access modes (badge, disclosure, roles, "Prompt hidden") | `lib/access-mode-copy.ts` for the copy, `components/teams/` for the badge + disclosure, `pages/teams/tabs/members/` for the mode cards and role columns — and read `docs/knowledgebase/authorization-and-authentificaiton.md` first |
| Change a primitive (button, dialog…) | `viewer/ui/` |
| Change routing logic | `viewer/hooks/useHashRoute.ts`, `main.tsx` |
| Change API calls | `viewer/api.ts` |
| Change data types | `models/` |
