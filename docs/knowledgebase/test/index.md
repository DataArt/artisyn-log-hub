# Test Knowledgebase

* [Test Strategy Overview](overview.md) - All suites (scenarios, contracts, algorithm units — the only unit tests left — legacy e2e), the 80 % scenario-coverage target, canonical commands and health checks, shared-resource rule, and which suite a new test belongs in
* [Client Unit Tests (Vitest)](client-unit-tests.md) - Only the doc-driven `*.algo.test.ts` remain in `client/` (component/logic units deleted 2026-10-16); runner config and setup files
* [Server Tests (Jest, algorithm tests only)](server-tests.md) - Only the doc-driven `*.algo.spec.ts` and the migration lock check remain (all `*.e2e-spec.ts` / other specs deleted 2026-10-16); no global setup, no DB, a `static` health check
* [Legacy E2E Tests (Playwright)](e2e-tests.md) - The remaining `tests/e2e/` specs not yet replaced by scenarios (drive the running dev app); no new specs here; storageState auth reuse, self-owned seed data, `@core`/extended split
* [Scenario suite (isolated stand)](scenarios.md) - `npm run test:scenarios`: builds `tmp/scenarios/stand/`, runs one stand per auth mode (A `none`, B `password-confirm`, C `password`) on its own port and `scn_*` schema, never touches the dev server; preflight, dev-state fingerprints, stand layout and lifecycle, `modes.ts`, the `stand`/`db`/`api`/`users` fixtures and the helpers (`waitForQueueIdle`, `shiftSessionTree`, `db-seed`, Mailpit, API keys, `golden.ts`), the golden sessions (`tests/golden/`, `check-arithmetic.mjs`, `view/golden-load.spec.ts`); health checks `scenarios-a/b/c`
* [API vs DB contract suite](contract-tests.md) - `npm run test:contract` (from `server/`): separate jest project, own app and `contract_*` schema with the world-v1 fixture, data registry of rows checked by one `runCase` against hand-written SQL, meta-test router vs registry; health check `contract`
* [Big pre-prod e2e test (manual skill)](big-prod-e2e-test.md) - `/big-prod-e2e-test [--keep]`: disposable amd64 stand built from the working tree, UI onboarding, hook install (current + previous release, local config, upgrade), eleven isolated `claude -p` sessions plus a legacy-hook session verified in the UI with per-scenario checks (Bash, denials, cost, work time, worktree), file categories, team and admin visibility, report with screenshot evidence; phases, session matrix, run-dir layout, cleanup, troubleshooting
* [Hook algorithm tests](overview.md#the-hook-algorithm-tests) - the three `*.algo.test.js` left in `hook/` (`npm test`, health check `hook-tests`, file list collected by `hook/scripts/run-tests.js`); the installer has no suite of its own — hook/installer behaviour is in the scenarios
