# Legacy Design Decisions Map

Read this when you meet a bare `T-NN` id in a commit message or in a document under `docs/`
(task folders, older plans) and need to know what it refers to.

Tasks were once numbered from a shared counter. That scheme is retired. The ids, together with the
task-bound `AC-*`, `FR-*` and `Design Decision N` references, have been removed from code
comments, test names and migration comments everywhere outside `docs/`: a comment now says what
the code does and why, without a task number. The ids remain only in commit messages and in
`docs/`, so this table decodes each one to its topic, a short summary of what it decided, and the
KB section that describes how the system works today.

- **Current behaviour** links to the article section that is the source of truth now. When it
  differs from the summary, the article wins.
- **"Not implemented"** means the work was never shipped: the idea is open, was dropped, or was
  closed as obsolete. Such rows have no link.
- **"Partly implemented"** names the shipped part, which the link describes, and the part that is
  still open.
