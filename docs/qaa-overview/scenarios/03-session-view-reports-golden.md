Date: 2026-10-13, branch `dev`. No tests were run and no code was changed. Everything below comes from reading the KB (`doc/knowledgebase`: llm-call-math, session-log-view, session-metrics-scope, change-surface, harness-usage-tab, api-reference, raw-logs-renderers), the code (`claude-extractor.ts`, `tool-stats.ts`, `otel-cost.sql.ts`, `SessionDetailPane.tsx`, the Summary detectors, `report-catalog.ts`, the pricing migrations) and the existing tests. The numbers in the golden-session tables were calculated by hand from the KB formulas and the rates in migrations `0008/0023/0033/0051` (sonnet-4-6 = 3/15/0.30/3.75(5m)/6.00(1h); haiku-4-5 = 1/5/0.10/1.25/2.00; opus-5 = 5/25/0.50/6.25/10.00; web search 0.01 per request). The UI label format was taken from the code and the existing e2e tests; check the exact texts when writing the test, the numbers are the contract.

## 1. Scope

Group: the session tabs (Summary, Info, Logs, Charts, Advisor, Statistics, Change surface, Harness usage, Raw Logs), repository analytics (timeline, work time, cost, tokens, tools, productivity, cache read ratio, change surface, horizontal view), reports (17 of them from `report-catalog.ts`, including Executive Summary and PDF), cost correctness.

One runner: Playwright (UI and the `request` fixture for the API). Data is uploaded the same way the hook does it: `POST /api/v1/logs?sessionId=…&type=artisyn|claude|claude-subagent[&parentSessionId=…]` (`text/plain`, NDJSON), then the test waits for the ingest queue. The scenarios have no direct DB inserts (the one exception, moved to the questions: the attribution reports need attribute definitions, which are set by a repository setting).

**Token Flow** (`VITE_ENABLE_TOKEN_FLOW`, OFF by default, admin-only, the Charts → Token Flow tab): no scenarios. The test "the tab is absent when the flag is off" goes to the PLATFORM group; `tests/e2e/token-flow.spec.ts` (28 tests) and 4 unit files are not part of this plan.

**Accepted assumption about the single time metric.** Work time (server `computeWorkTime`, client `totalWorkTimeMs`) = the sum over qualifying prompts of `(the last assistant event before the next prompt) − (the prompt time)`. `api-reference.md` says "sum of turn_duration" for `TimelineSession.workTimeMs`; that is stale (in the code `session_stats.work_time_ms` is computed from timestamps). The golden sessions do not use `turn_duration` events as a source of numbers.

## 2. GOLDEN SESSIONS

### 2.1 Principles

1. Nine fixtures (eight written by hand, one generated by a script from a deterministic rule). Each is a realistic set of Claude Code JSONL lines plus the hook's artisyn lines (`git.repo`, `prompt`), written the way a real hook would send them. The fixtures live in `tests/golden/<id>/` (`artisyn.jsonl`, `claude.jsonl`, `subagents/<agent-id>.jsonl`, `expected.json`). None is a copy of a real session (to avoid leaking data).
2. Times are written with the template `{{A+1d 10:00:00}}`, where `A` = Monday 00:00 UTC two weeks ago (week W1 = A..A+6d, W2 = A+7d..A+13d). This keeps the analytics ranges and the weekly buckets stable on any run day, and all sessions fall in the past. Identifiers are templated as `{{RUN}}-gs01`, so parallel workers do not overlap (the rule from `seed.ts`).
3. The expected numbers live in `expected.json` next to the fixture as **literals** (not formulas in the test). The test reads `E.gs04.costUsd`. An `EXPECTED.md` with the same table is for people to read; it matches the tables below.
4. All numbers are chosen so that the 4-digit value shown in the UI does not sit on a rounding boundary (tokens are multiples of 80 for the sonnet 5m cache write, and so on; the totals are checked against the formula). If a fixture changes, the number is changed by hand and reviewed like code.
5. The test takes rates only from `GET /api/v1/model-pricing`, as a "rates have not changed" check (one assertion in S-COST-03); every other assertion uses the literals. If a pricing migration changes a rate, one scenario and one table break, not 6 files (see question G4 from the deleted cleanup inventory; current state: [KB test](../../knowledgebase/test/index.md)).
6. All sessions belong to user U1 (the owner of repository `REPO-GOLD`). A second user U2 is needed only for the 403 checks (S-SESS-12, S-SESS-13).
