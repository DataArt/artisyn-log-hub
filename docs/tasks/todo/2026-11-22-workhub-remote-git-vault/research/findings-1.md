## Requirements summary
Work Hub users get per-user **connections** (FR-1, FR-2). A connection has a name, a kind (`git` now, `api` later), a provider, a base URL, an auth method, a policy and a secret that lives only in the vault. Providers are described by a descriptor table: GitHub, GitLab (gitlab.com or self-managed), Azure DevOps and generic HTTPS git. Auth methods are an SSH key generated by WH (preselected; its private key never leaves WH), an uploaded SSH key with optional passphrase, or a PAT over HTTPS. SSH host keys are pinned per connection on the first "Test".

Secrets are stored only through `secrets.rs` and never enter a container, volume, checkpoint, recording or log (FR-3).

Containers reach the git host only through a **WH git proxy sidecar**. `.git/config` holds only the proxy URL. A credential helper reads a scoped, revocable capability from the container's tmpfs `/tmp`, which the server rewrites on every container start. The sidecar adds the credential itself, over SSH or HTTPS (FR-6). It also enforces the push policy per container; by default a force push to, or deletion of, the remote default branch is rejected (FR-7).

Other features:
- **Create a workspace by cloning** (FR-4): pasted URL; branch list from `ls-remote` through the proxy; progress with Cancel; a failure leaves nothing behind.
- **Attach a remote to an existing workspace** (FR-5): only connections explicitly granted to that workspace can be used.
- **Push when closing a workstream** (FR-8): which branch is pushed depends on the close mode; the PR/MR link comes from the descriptor; a failed push does not undo the close.
- **"Expose to agent"** (FR-10): an opt-in env var. It is never available for a WH-generated key, and it needs several env var pairs instead of today's one.
- **"Test"** (FR-11): checks the credential and shows success or a readable error.
- **`kind = api`** (FR-9): design only. The model and route layout must allow it without changing existing columns or the git proxy.

Non-functional requirements: additive migrations; backward compatible; works offline; agent-neutral; adding a provider means adding a descriptor row only.

## Wireframes
All files are in `docs/tasks/todo/2026-11-22-workhub-remote-git-vault/wireframes/`.
- **`connections-page.svg`**: a new account-menu item "🔑 Connections" above "Edit email", so it is a user-level page, not a workspace page. Table columns: NAME/PROVIDER, AUTH, STATUS, GRANTED TO, ACTIONS (Test, Edit, Delete…, Update key…).
  - Auth shows the SSH fingerprint, or "secret set ••••a1b2" with the updated date.
  - Status is "Connected", "Rejected by host", or "Test failed" with "401: credential rejected by host". It comes from the last Test or the last proxy use, so the server must store it.
  - A "👁 Visible to the agent" badge appears when expose is on. "Granted to" shows "N workspaces" or "none · Grant…".
  - Empty state: "No connections yet. Work Hub works fully without them."
- **`add-connection-dialog.svg`**: three steps.
  1. Provider tiles (GH, GL, AZ, Other); for GitLab a gitlab.com / Self-managed choice plus a URL field; name; auth method (SSH key or PAT); "Generate a key in Work Hub ★ Recommended" or "Upload my private key".
  2. Copy the public key (comment `workhub-<name>`), a link to the host's SSH keys page, then Test → a "First connection to <host>" fingerprint prompt with "Trust and pin" → "✓ Test passed · authenticated as dtsyplakov". The server must return the authenticated username.
  3. PAT: a "Create token on GitHub ↗" link with scopes pre-filled; a Username field shown only when the host needs one; a write-only Token field; an "Expose to agent as env var" toggle; Test / Cancel / Save.
- **`new-workspace-from-remote.svg`**: "Start from: Empty repository | Clone from a connection". Connection select with an "Add connection…" link, repository URL, branch select with the remote default preselected. Clone progress ("Receiving objects 48% (12 034 / 25 070), 31 MiB") with Cancel. Two error states: clone failed (git stderr) and credential rejected (with "Update key in Connections").
- **`workspace-settings-remote.svg`**: the Settings row "Repository: none — started empty" becomes "Remotes". One card per remote: name, connection, status, URL, auth, policy summary; actions Test / Push policy… / Detach…; "＋ Attach remote".
  - The Attach dialog has remote name, a connection select (non-granted connections show "not granted here · Grant…"), URL and two policy checkboxes: "Block force push to default branch" (on) and "Allow push only to ws/* branches".
  - The policy is therefore stored **per remote** (the requirements allow per connection or per remote).
- **`close-workstream-push.svg`**: a new "Push main to origin" checkbox in the existing close dialog with a connection chip. Hidden when there is no remote; disabled for "Already merged elsewhere".
  - Result states: "✓ Pushed ws/fix-login to origin" with "Create pull request ↗" ("merge request" on GitLab); "Push rejected" with the policy message and "The workstream is closed locally"; "credential rejected by the host" with "Update key in Connections".

## Knowledgebase
- **`docs/knowledgebase/work-hub.md`** (mandatory). Points that matter for this task:
  - Only `server/src/agent/{mod,claude}.rs` may name the agent; `scripts/agent-names-check.mjs` enforces this.
  - The secret store is meant for every future secret.
  - Container model: every container gets a tmpfs `/tmp`, the default bridge network, no published ports, and runs as the workspace's container user. The workstream container gets a copy of the workspace volumes, so the remote config in `/workspace/repo/.git/config` carries into the workstream's worktree.
  - Docker objects are named `wh-*`, carry the instance label, and are cleaned up only by that label. A sidecar container needs a new `Role` and must follow these rules.
  - The licence check allows only permissive licences, with no MPL/weak-copyleft exception. This constrains any SSH/crypto crate.
  - Config vars must be documented in `.env.example`, the KB table and `work-hub/README.md`, which must stay offline and self-contained.
  - Tests are three kinds: algorithm docs `workhub-*`, the contract registry, and scenarios `@S-WH-NN`.
- **`docs/knowledgebase/algorithms/workhub-repo-path.md`** (and `workhub-names.md` / `workhub-devcontainer-subset.md`): show the algorithm doc format (front matter `type: "Algorithm"`, `reviewed`, `reviewer`; sections Purpose / Code / Twins) with rows in `docs/algorithm-examples/<name>.json` (`id`, `input`, `expected`, `note`). These are the template for new docs:
  - URL parsing (SSH/HTTPS clone URL → host/owner/repo → proxy URL),
  - the descriptor table (username/header convention, PR URL),
  - the push-policy decision,
  - env var name validation (FR-10).
- **`docs/knowledgebase/algorithms/auth-startup-config.md`** and `local-request-detection`: under `AUTH_MODE=none` the container's default gateway is trusted as local (`server/src/auth/local_request.rs:1-30`). Keep this in mind if a proxy endpoint ever lives on the main server port.
- `CLAUDE.md` → Work Hub: commands are run from `work-hub/` (`npm run lint`, `typecheck`, `test:algo`, `build`, `test:contract`, `test:scenarios`). Scenario coverage is not measured for Work Hub.

## Existing patterns
**Secrets and crypto**
- `work-hub/server/src/secrets.rs:21-27` — names allow only `[a-z0-9-]`, 1–64 characters. Connection secret names must fit this, e.g. `conn-<uuid>-key`: `conn-` + 36-character uuid + `-key` = 44 characters, which fits.
- `secrets.rs:66-99`, `103-132`, `140-149`, `152-159` — `put` (AES-256-GCM, AAD `<user id>/<name>`, atomic tmp file + rename, 0600), `get` (returns `None` when missing or undecryptable), `delete`, `delete_all`. Account deletion already wipes the user's whole secret dir (`workspaces/mod.rs:1049`).
- `work-hub/server/src/auth/tokens.rs:66-80` — `new_token()` (32 random bytes → 64 hex characters) and `token_hash()` (SHA-256 hex). The pattern for an unguessable capability, stored hashed in the DB.

**Agent env and expose-to-agent**
- `work-hub/server/src/agent/mod.rs:58-70` — `token_env()` and `token_secret()` (`<agent id>-token`).
- `work-hub/server/src/workspaces/login.rs:66-95` — `agent_token` / `agent_env` return one `(name, value)` pair. FR-10 changes this into a list.
- `work-hub/server/src/terminal/tmux.rs:133-166` — `SecretEnv<'a> = Option<(&str, &str)>`. It is passed through exec stdin (`IFS= read -r WH_SECRET` → `-e NAME=$WH_SECRET`) and validated by `is_env_name` (`[A-Z0-9_]`, but this does not reject a leading digit, unlike FR-10's regex). This needs to become a list of pairs.
- Callers that pass the secret:
  - `workstreams/mod.rs:585-600` (open: chat),
  - `workstreams/mod.rs:704-745` (ensure running: resume / respawn),
  - `workspaces/configure.rs:35-70` (configure),
  - `workspaces/login.rs:273`.
- `agent::with_agent_env` (`agent/mod.rs:73-84`) — `containerEnv` merge; FR-10 must reject names that clash with it.

- `docker/names.rs:35-56` — the `Role` enum (workspace / workstream / helper / checkpoint / built). It needs e.g. `Sidecar` plus a name function, under the label rules at lines 118-173.

## Open gaps
1. **No network layer.** There is no Docker network code; everything runs on the default `bridge`, which has no DNS. Reaching the sidecar (user-defined network, a fixed IP, or a per-container network) has to be designed from scratch, along with how the sidecar talks to the WH server (sidecar ↔ server control channel or shared vault access). The dockerized app sits on the compose network, not the default bridge.
2. **No sidecar image or process.** Nothing runs long-lived besides workspace/workstream containers. To decide: the sidecar's image (built from an embedded context like the default image, or the server binary itself), its lifecycle (ensure at startup plus the reconciler), its Role/label, and how it gets decrypted secrets without them touching disk.
3. **No HTTP client, SSH or keygen crates.** There is no non-dev HTTP client (`reqwest` is a dev-dependency; `openidconnect` pulls its own reqwest with rustls), no SSH crate, and no ed25519 keygen or host-key fingerprinting. Choosing crates (e.g. `ssh-key`/`ed25519-dalek`, `russh`, or shelling out to `git`/`ssh` inside the sidecar) must pass `license-check.mjs`, which allows no MPL.
4. **No git smart-HTTP proxying or ref-update parsing.** Policy enforcement (force push or deletion of the default branch) needs the receive-pack ref update list (old/new sha), and detecting a force push needs ancestry, which the sidecar can only check with an object store or a `git` in the sidecar.
5. **No credential-helper or tmpfs-write-on-start hook.** There is no single "container started" hook; the start sites are spread out (listed above). Also to decide: where the helper script lives (`/tmp` vs. a global gitconfig in the image; user-defined devcontainer images may not have `/etc/gitconfig` set), and what to do for images without `sh`.
6. **`SecretEnv` takes one pair.** FR-10 needs a list type, plus a validator matching `^[A-Z_][A-Z0-9_]*$` (the current `is_env_name` allows a leading digit).
7. **No DB tables for connections, grants, remotes, policy, capabilities or test status.** Everything is new in migration 0005: connection (kind/provider/auth_method/secret ref/last4/updated_at/status/last_error/host-key pin/expose env name), grant (connection × workspace), workspace remote (name/url/connection/policy), capability (hash, container/workspace). Whether the descriptor table lives in code or the DB is not decided; requirements imply code plus algorithm rows.
8. **No clone progress or cancel mechanism.** Create is a single blocking `POST` today, and there is no streaming or job endpoint for progress. A long-running clone needs a polling job or a WebSocket, and cancel needs `Undo`.
9. **No user-level settings page in the web app.** Settings is per workspace (`/w/:wsId/settings`); a Connections route and page are new.
10. **No test git host on the stand.** The scenario and contract stands have no git server, SSH server or fake provider API. Scenarios for FR-1a, FR-4, FR-6, FR-7, FR-8 and FR-11 need a local fake host (e.g. a container with git-http-backend and sshd, built like the fake-agent image) plus fake descriptor test endpoints. Real GitHub/GitLab cannot be used.
11. **No KB article for credentials or the proxy yet.** A new `docs/knowledgebase/` article (or a `work-hub.md` section) and its `index.md` entry are needed, plus README / `.env.example` updates for any new env vars, e.g. the sidecar image or network name.
