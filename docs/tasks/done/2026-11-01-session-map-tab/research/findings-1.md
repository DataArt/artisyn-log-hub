# Research findings 1 — 2026-11-03

**Requirements summary**
New "Session Map" tab (`session-map`, group `overview`, always shown, promoted in "What happened" lens after `agent-tree`) rendering one session's agent tree on one screen: main card on top (own cost/tree cost/own share, tool-family mix, calls + top tools, failures, peak ctx vs model window); one column per workflow run (start order) + one for directly-spawned agents; each column = group header card + agent cards (cost with share and zone bar, tool mix, calls/top tools, failed badge, peak ctx, duration), nested sub-agents indented under their parent; card states by time position (future/running/done); highlight (failed/top-5) and order (start/cost); side panel with selected card metrics + filter chips + call log (click → move time position, open → `ToolCallDetailModal`); bottom timeline (stacked bins by tool family, failure marks, cumulative cost line, scrubbable); header counters at time position; realtime mode for live session (10 s poll, "Live" control returns to following now) and replay mode for finished (play/speeds/scrub). Server: new `GET .../sessions/:sessionId/logs/delta?cursor=&teamId=` with opaque base64url cursor carrying per-`(session,log_type)` row `updated_at` + line count + last-line fingerprint; returns new lines, new sessions with linkage, `subagentStats`, `workflows` (or `null` if unchanged), liveness, server time, next cursor; stale → `200 {reload:true}`; empty poll must read no `logs.body`; same access as `/logs`. Liveness from `otel_session_state`; no OTEL ⇒ finished (replay). Per-call cost = new algorithm doc. No hook/ingest change, no new chart lib, ≤100 ms rerender at 50 agents/1 000 calls.

**Open gaps**
1. "Final result" for a sub-agent: FR-5 "running" = no `tool_result` for its Task/Agent call; for background agents `tool_result` arrives at launch, real completion is a later task-notification (KB: often never reaches parent transcript). Need explicit rule (e.g. task-notification match, or last-activity within realtime window).
2. `WorkflowRun` carries no start time, run number, or kind (`client/src/models/workflows.ts`). Column start order and "run #N" must be derived (e.g. Workflow `tool_use` timestamp via `toolUseId`, or earliest agent `startMs`). Running runs have `wfId=null`/`agentSessionIds=[]` → their agents have no column until the run completes; plan needs a rule (e.g. group by `sessions.workflow_run_id` returned in delta linkage).
3. Cursor timestamp precision: `logs.updated_at` is microsecond `timestamptz`; JS `Date` truncates to ms — cursor should carry `updated_at::text` or epoch micros. Fingerprint fallback hash (e.g. `md5(line::text)`) undefined; artisyn lines generally have no `uuid`.
4. Reading `body[n:]` without full parse: no helper exists; changed row still detoasts whole body in SQL (`jsonb_array_elements WITH ORDINALITY WHERE n > k` + `body->(n-1)` fingerprint) — acceptable since only changed rows. Detecting whether root `claude` row "changed" (to recompute `workflows`) requires that full parse server-side.
5. `/logs` access logic is inline; needs extracting into a shared method; `extractWorkflows`+BFS also needs extracting so delta and `/logs` keep identical semantics (same 404 on missing claude log, same 403).
6. Existing watermark poll interaction: `useRepositoryData.ts` already silently refetches `/logs` when `endTime` changes (15 s) — contradicts "only refresh is the header button"; plan must decide whether that poll is suppressed while the Map tab is open (otherwise full payload re-downloaded anyway).
7. No tool-family taxonomy exists in client; only PoC regexes (`docs/pocs/2026-11-01-2253-session-map-2d/index.html:161-166`: explore/edit/shell/mcp/orch/other with MCP as `^mcp:` form vs app's `mcp__`). Wireframe legend lists Skill·Agent·Workflow but PoC also puts ToolSearch/TaskStop/Cron* there. Colours not defined in chart palette (`lib/chart-colors.ts`) → family colours need tokens.
8. Per-call cost algorithm (message weight = own `usage` priced, split evenly over its `tool_use` blocks) is new → needs algorithm doc + new `*.algo.test.ts` alongside (test policy allows). A shared exported `ZoneLegend` decision (one exported, six private copies).
9. "Run" concept for a nested Workflow inside a sub-agent: out of scope of `agentSessionIds` — such agents fall into neither column; placement rule undefined.
10. Liveness vs OTEL tab permission: OTEL session route has no analytics gate, but client hides OTEL tab via `canSeeTeamWideTabs`; delta must compute `live` itself from `otel_session_state` (not call the OTEL reader) — no helper exposing only `{live,lastActivityAt}` today.
11. No existing scenario covers a live growing transcript + OTEL realtime together; `s-otel-01` is OTEL-only — FR-9/FR-13 steps likely fit `s-otel-01` (it already uploads transcripts + realtime batches); FR-2..FR-8 fit `s-sess-04`/`s-sess-03`. NFR ≤100 ms perf-mark check needs the PoC-sized session; none exists in `tests/golden` (largest are gs-05/gs-09).
12. User doc: "Session Map" section in `user-docs/session-log.md` + `nav.json`/help wiring needed (offline-first, screen-registry `docRef`).
