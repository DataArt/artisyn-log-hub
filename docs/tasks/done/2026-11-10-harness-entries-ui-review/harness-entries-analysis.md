### Reading of the hook-identity facet (Design Decision 4)

- The facet shows hooks **seen running**, not hooks configured — this is how FR-6's "configured hook names" is
  read.
- `status-text` means the hook's `command` field holds its status message rather than a command line. In this
  sample that is always Log Hub's own hook.
- So the facet only separates hooks with a status message from those without one. A hook-health proposal must
  label rows by `command`, and that label may be status text.

### Reading of "Usage" (Design Decision 10)

- `tab-ids.ts` has no tab labelled "Usage": session tab id `usage` is labelled "Statistics" and `context-usage`
  is "Context Usage". FR-3's "Usage" is read as both tabs.

### Stop-time note

Sessions whose last turn (Design Decision 7 rule) lacks the entry:

| Entry missing in last turn | All (291) | Interactive (273) | `claude -p` (18) |
|---|---|---|---|
| `turn_duration` | 49 | 31 | 18 |
| `stop_hook_summary` | 53 | 44 | 9 |
| Stop-event `hook_success` | 61 | 52 | 9 |
| all three | 40 | 31 | 9 |

- Interactive sessions: every one that lacks `turn_duration` lacks all three entries, which fits a last turn not
  yet uploaded or not flushed. A further 13 sessions lack only `stop_hook_summary`, and 21 lack only the Stop
  `hook_success`.
- `claude -p`: 18 of 18 sessions have no `turn_duration` anywhere, so turn timing there needs the "≈" fallback
  (time from the prompt to the last assistant line).
- Repos per `repositories.hook_version`: < 2.8.0 — 0; ≥ 2.8.0 — 4 (2.25.0 ×1, 2.31.2 ×3); `unknown` — 1.
- So an old hook does not explain the missing last-turn entries in this sample; the likely causes are sessions
  still open at the cutoff or killed before SessionEnd. `repositories.hook_version` holds only the current
  per-repo version, so an older hook having uploaded some sessions earlier cannot be ruled out.
- Implication: a per-turn chip reads "not recorded yet", never zero, and aggregates count such turns as unknown.

## 3. Item details

### Rules shared by every card

- **Turn assignment (Design Decision 7).** An entry belongs to the turn whose user prompt is the latest one at or before
  its timestamp — the `compactBoundariesBetween` rule (`compact-boundary-placement.ts:9-26`). Stop-time entries
  (`turn_duration`, `stop_hook_summary`, Stop-event `hook_success`) that follow the turn's last assistant line belong
  to that same turn.
- **Not uploaded yet.** Stop-time entries are written after the Stop hooks, so the upload that runs at Stop cannot
  carry them. They arrive with the next upload (the next prompt's background upload or the next Stop) or with the
  SessionEnd flush (hook ≥ 2.8.0). Until then the last turn reads **"not recorded yet"**, never zero, and server
  aggregates count such turns as unknown. In the survey, 31 of 273 interactive sessions lack all three in the last
  turn.
- **Hook < 2.8.0.** No SessionEnd flush, so the last turn of a session that ends without a later upload never gets
  its Stop-time entries. The UI shows "not recorded" for that turn. Server aggregates treat the session's Stop-time
  data as incomplete, so these sessions are a lower bound, not a zero. Older turns are unaffected.
- **Unknown shape.** Every reader checks the fields it needs. A known type with a missing or renamed field renders
  "—" for that field and never throws. An unknown type renders nothing on Logs and stays visible on Raw Logs.
  Server extractors count unparseable entries per session (`unparsed`), so a Claude Code format change shows up as a
  rising count, not as a silent zero.
- **No hook change.** Every item reads the `claude` transcript, which every hook version already uploads. Older
  hooks keep working, and no Hook API change is needed. Server items work on old sessions only after a re-extraction
  (a version column like `session_stats.list_flags_version`).
- **Privacy and neutrality (FR-2, Design Decisions 8 and 17).**
  - No email, no absolute paths. Paths are reduced to repo-relative by the existing setup-neutral reducers
    (`toUserDisplayPath`, `toRepoRelative`, `normaliseClientPath`); an out-of-repo path becomes its basename.
  - Per-turn Logs markup shows text only if the Logs tab already shows it. Any other text (stderr, snippets,
    diagnostic messages, banners) stays in the "›" Raw Logs modal, which already shows it.
  - Repo/team items carry only counts, durations, codes and repo-relative paths.
  - Labels never name an IDE, an OS, a language or this repo's hooks. They use the payload's own `source`,
    `ideName`, `hookEvent` and hook identity.
- **Server items** must not read `logs.body` per request (`server-conventions.md:15`). Each one names the ingest
  extractor that fills a derived table and the table that the route reads.
- **Sub-agents.** Per-turn markup covers the main transcript. Signals inside `SubAgentDetail` are a separate
  follow-up (Design Decision 12). Server aggregates include sub-agent lines, attributed to the root session as in the
  survey.

### S0 · Signal sources strip and Signals toolbar (supporting, no type of its own)

- **Shown:** the toolbar "Signals: Show · Only turns with issues" with session totals (wireframe element 1). Below

  none), diagnostics `source` values or "none seen", `entrypoint` and the CC version. The toolbar state is the URL
  param `signals=issues` (Design Decision 11).
- **Fields read:** `entrypoint`, `version` (any line); `ideName` of `*_in_ide`; `diagnostics.files[].diagnostics[].source`;
  `hook_success` / `stop_hook_summary.hookInfos[].command`.
- **Client / server:** client-only from `/logs`, with the facet rules of Design Decision 4.
- **Hook change:** none.
- **`artisyn`-log equivalent:** the harness snapshot (installed skills, plugins, MCP) and `hook-status` (Log Hub's
  hook version). Preferred source: the transcript, because it shows what actually ran in this session, for any
  hook or IDE, not what is installed.
- **Degraded:** a missing producer reads "none seen", so a missing group reads as "not produced", not as "no
  problems" (element 8). A missing `entrypoint` or `version` reads "unknown".
- **Privacy:** facet values only.
- **Producer / absent:** derived from the other cards' producers.

<a id="a1"></a>

### A1 · Turn timing chip

- **Shown:** in `PromptTurnHeader.tsx`, "turn 0:04:21 · 61 msgs · hooks 4.6s" (wireframe element 3). The hooks part
  is the sum of the turn's `hook_success.durationMs`.
- **Fields read:** `system:turn_duration.durationMs`, `messageCount`, `pendingBackgroundAgentCount`,
  `pendingWorkflowCount`; `hook_success.durationMs`.
- **Client / server:** client-only. Repo-level waiting analytics belong to task
  `2026-11-09-session-waiting-breakdown`.
- **Hook change:** none.
- **`artisyn`-log equivalent:** `prompt_start` / `prompt_stop` segments, which are the hook's work-time
  calculation. Preferred source: `turn_duration`. It is Claude Code's own measure, carries the message count and
  exists without Log Hub's hook. An Escape-interrupted turn's segment closes only at the next `prompt_start`, so it
  overstates. The artisyn segments stay a cross-check.
- **Degraded:**
  - Absent (`claude -p`: 18 of 18 sessions; older CC): "≈ 0:00:46", the time from the prompt to the turn's last
    assistant line, marked "≈".
  - Last turn not uploaded yet, or hook < 2.8.0 without a later upload: "turn timing: not recorded yet".
  - Unknown shape (no numeric `durationMs`): "turn timing: not recorded".
  - No hooks in the session: the "hooks" part is omitted.
- **Privacy:** durations and counts only.
- **Producer / absent:** CC harness at the end of an interactive turn; absent in `claude -p`. `hook_success` only
  with configured hooks.

<a id="a2"></a>

### A2 · Signals "Hooks" group

- **Shown:** collapsed chip "1 hook error" in the turn's Signals section (element 4). Expanded
  ([signals section](wireframes/logs-turn-signals-section.svg), HOOKS): one row per error with event, exit code
  and duration, plus one "ok ×N" row with the total and the slowest hook. A "system message" count comes from
  `hook_system_message`, and a "blocked continuation" flag from `stop_hook_summary.preventedContinuation`.
- **Fields read:** `hook_success` / `hook_non_blocking_error`: `hookEvent`, `command`, `exitCode`, `durationMs`;

**Section order in a turn:** header chips → prompt → metrics row → interjection markers → Skills → Rules → Tools →
**Signals** → Files → Images → Agents → Workflows. Signals sits after Tools because most of its rows (hook runs,
truncated reads, diagnostics on just-edited files) are reactions to tool calls. It sits before Files because Files
lists what the agent touched, and Signals rows link to those paths. The section is hidden when the turn has no
Signals rows.

**Naming.**

- **Signals** is the per-turn section; its groups are Hooks, IDE, Edited outside the agent, Diagnostics and Context.
- **Signal sources** is the session strip that says which producers were present.
- "Issues" was rejected because most rows are not problems: ok hook runs, IDE selections. "Harness" was rejected
  because it clashes with the Harness usage tab.
- Group labels name the entry's own concept, never a setup (Design Decision 17). Diagnostics sub-groups use the raw
  `source` value, and hook rows use the hook identity.
- "Only turns with issues" counts hook errors, non-blocking errors, never-fixed error diagnostics, interjections,
  outside edits and compactions.
