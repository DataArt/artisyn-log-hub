# Implementation Plan: Mount the Export/Import Staging Dir in the Release Compose

## TL;DR

- Release compose (and the `big-prod-e2e-test` stand copy) gets one more `app` bind mount:
  `${LOG_HUB_DATA_DIR}/export-import:/app/dist/export-import`.
- New server helper `server/src/common/repeated-failure-log.ts` (`RepeatedFailureLog` with
  `failed(err)` / `succeeded()`): logs a sweep failure once per distinct message, repeats at DEBUG,
  one INFO on recovery. Used by `ExportImportJobCleanupScheduler` and
  `TurnEndAdvisorOrphanCleanupScheduler`.
- No DB, API, env var default, hook or npm dependency changes. Backward compatible both ways.
- Docs: `INSTALL.md`, `LOCAL-BUNDLE.md`, `user-docs/component-reference.md` (+ `npm run build:help`),
  two KB articles.
- Test: one new step 20 in scenario `s-repo-11`, plus `EXPORT_IMPORT_CLEANUP_INTERVAL_MS: '2000'`
  in the scenario stand's fast-tick env.

## Design Decisions

- DD-1: Helper is a plain class (not a Nest provider), constructed per scheduler with its `Logger`
  and a label (`'Export/import job cleanup sweep'`, `'Turn-end advisor orphan cleanup sweep'`); the
  existing message prefix `<label> failed: <message>` is kept so log searches and AC2 still match.
- DD-2: Failure key is `err instanceof Error ? err.message : String(err)`, compared to the previous
  failure only; state is two fields (`lastKey: string | null`, `failedCount: number`).
- DD-3: Verified in step 2 — `fs.mkdirSync(dir, { recursive: true })` throws `EEXIST` when `dir` is a
  regular file (all OSes), so `sweepOrphanFiles()` fails via `resolveExportImportStagingDir()`
  (`server/src/logs/export-import-zip.ts:30-34`). Scenario stand runs Playwright with `workers: 1`
  (`playwright.scenarios.config.ts:33`), single process, `cwd = STAND_RUN_DIR`
  (`scripts/scenarios/stand.mjs:192`), `EXPORT_IMPORT_DIR = <runDir>/export-import`
  (`tests/scenarios/modes.ts:152`), so breaking the dir for a few seconds cannot hit another spec.
- DD-4: The app logger writes every level (`trace`) to `<cwd>/logs/app-*.log`
  (`server/src/common/app-logger.ts`), so the `recovered` INFO is asserted by reading
  `path.join(stand.runDir, 'logs')` `app-*.log` files; the single ERROR via
  `GET /api/v1/admin/error-logs` (`{ entries: [{ timestamp, level, message, … }] }`) as an admin.
- DD-5: Installers need no change: they do not pre-create data subdirs; Docker creates the bind
  source on first start. `scripts/local-loghub.js` copies the template compose
  (`scripts/local-loghub.js:38`) and needs no change.

- [x] `release-template/docker-compose.yml`: after the `upload-queue` volume line (`:81`) add

  escaping) after `:127`, and add `'export-import'` to the subdir array at `:161`.
- [x] Create `server/src/common/repeated-failure-log.ts`: exported class `RepeatedFailureLog`,
  constructor `(logger: Logger, label: string)`, fields `lastKey: string | null = null`,
  `failedCount = 0`. `failed(err: unknown)`: key = `err.message` or `String(err)`; `failedCount++`;
  if key ≠ `lastKey` → `logger.error(\`${label} failed: ${key} (repeats suppressed until the sweep recovers)\`, err.stack)`,
  set `lastKey`; else `logger.debug(\`${label} failed again: ${key}\`)`.
- [x] Same file, `succeeded()`: if `failedCount > 0` → `logger.log(\`${label} recovered after ${failedCount} failed sweeps\`)`;
  reset `lastKey = null`, `failedCount = 0`. Add a short JSDoc on the class (per-worker in-memory
  state, previous-failure-only key, restart logs the first failure again).
- [x] `ExportImportJobCleanupScheduler` (`server/src/logs/export-import-job-cleanup.scheduler.ts`):
  add `private readonly sweepFailures = new RepeatedFailureLog(this.logger, 'Export/import job cleanup sweep')`;

  catch body (`:96-101`) with `this.sweepFailures.failed(err)`. Same change in
