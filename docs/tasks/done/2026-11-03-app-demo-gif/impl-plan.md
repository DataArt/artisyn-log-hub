# Implementation plan: App Demo GIF and Media Carousel for README and Site Home Page

## TL;DR

- New manual tool `scripts/site/record-demo.mjs` (ESM, Playwright, read-only against a running Log Hub): modes `tour`, `items`, `all`, `--only <id>`; writes only its own listed files under `site/assets/demo/` plus a manifest `site/assets/demo/items.json`; run by hand via the new root script `npm run record:demo`. Not part of `build:site` or any health check.
- New devDependencies at the repo root: `gifenc` ^1.0.3 (GIF encoder, named in FR-6) and `pngjs` ^7.0.0 (decodes Playwright PNG screenshots into RGBA for gifenc); both MIT, listed in the third-party docs.
- New site assets: `site/assets/carousel.js` (vanilla IIFE) and carousel rules appended to `site/assets/theme.css` with one new token `--frame-bg`; `site/pages/home.html` gets a "See it in action" section after the hero.
- Committed media (generated by the script): `app-tour.gif` (+ `app-tour.png` first frame), 21 stills, 10 clips (+ first-frame PNG each), 32 thumbnails, `items.json`.
- `README.md` embeds `site/assets/demo/app-tour.gif` after the Docs · Site · Deck links.
- Docs: KB `user-docs-and-site.md` (Screenshots rows + "Demo media" subsection), QA doc §S-SITE-01, changelog entry.
- No server, client, DB or API change; no `build-site.mjs` change (`site/assets/**` is already copied as is).
- Tests: one new step in the existing scenario `@S-SITE-01` (+ `.gif`/`.jpg` content types, timeout raised).

## Design Decisions

1. **Script base.** `scripts/site/record-demo.mjs` is the PoC's `capture.mjs` (`docs/pocs/2026-11-03-2041-site-media-carousel/capture.mjs`) promoted: same presentation-mode init script (`:39-69`), `newPage` with `POST /api/v1/auth/identify` (`:93-99`), `settle` (`:102-106`), `open` (`:108-123`), `overflow`/`openFitted` (`:126-161`) and GIF loop/encoder (`:175-222`), plus the thumbnail renderer and `gifDurationMs` from `preview.mjs` (`:52-57`, `:73-87`).
2. **ESM exemption.** The header documents the exemption from the `nodejs-script` CJS/sync rule exactly like `scripts/site/build-site.mjs:14-16`: Playwright is async-only and `gifenc` ships as ESM; everything else follows the rule. Import `chromium` from `@playwright/test` (the root devDependency; no separate `playwright` package); the Chromium browser is the one `npx playwright install chromium` already provides for the scenario suite (sync fs, `path.join`, diagnostics on stderr, explicit exit codes).
3. **CLI.** `node scripts/site/record-demo.mjs <tour|items|all> [--only <id>[,<id>]]`; root `package.json` script `"record:demo": "node scripts/site/record-demo.mjs"`. Exit 2 on bad arguments/env, 1 on a failed scene (all scene errors collected and printed), 0 otherwise. Prints one line per file: id, fit factor, faded panes, size.
4. **Env (all required, no defaults, never written to tracked files):** `LOGHUB_URL` (http/https only), `LOGHUB_EMAIL` (owner of the demo repo), `LOGHUB_REPO` (repo id), `SESSION_COST` (a costly session with English prompts), `SESSION_AGENTS` (a session with a workflow and sub-agents). Missing or malformed → exit 2 naming the variable. The script never starts a server and only issues `identify` plus GET navigation.
5. **Output guard.** Output dir is fixed: `site/assets/demo/` (and `thumbs/` under it) resolved from the script location; the script creates it if missing, writes only the file names derived from the scene catalog plus `items.json`, never deletes anything, and prints a warning listing any other file it finds there (stale media left for the human to remove).
6. **File naming (contract shared by script, page and scenario).** Constant `TOUR_ID = 'app-tour'` is the tour's catalog id (valid for `--only`). Under `site/assets/demo/`: tour `app-tour.gif` + its first frame `app-tour.png`; still `<id>.png` (2560×1600); clip `<id>.gif` (960×600) + first frame `<id>.png`; thumbnail `thumbs/<id>.jpg` (256×160, JPEG q80); manifest `items.json`. `<id>` is the catalog id (kebab-case).
7. **Capture geometry.** Stills: viewport 1280×800, DPR 2 → 2560×1600. GIFs (tour and clips): DPR 0.75 → 960×600 (one GIF size keeps clips under budget; the 16:10 frame is the same). Fit: overflow factor k ≤ 1.5 grows the viewport by k and divides DPR by k; still-overflowing panes get the 72 px bottom mask fade. Light color scheme (`colorScheme: 'light'`).
8. **First frames and thumbnails.** For every GIF the first kept frame is also written as `<id>.png` (the reduced-motion still); thumbnails are rendered from the still / first-frame PNG on a `file://` 256×160 page with `object-fit: contain` on `#fff` (PoC `preview.mjs:73-87`); the thumb page is written to `tmp/record-demo/thumb.html`, not into `site/`.
9. **GIF encoding.** Grab screenshots in a loop, keep at most 10 fps, merge byte-identical consecutive frames, one 256-color palette per frame, `delay` = time to the next kept frame (gifenc rounds to 10 ms), `repeat: 0` (loop forever). PNG decode via `pngjs` `PNG.sync.read`.
10. **Budgets enforced by the script (fail the item, exit 1):** tour ≤ 5,000,000 bytes and 22–28 s; clip ≤ 3,000,000 bytes and 5–8 s; still ≤ 600,000 bytes; catalog files in `site/assets/demo/` (including `thumbs/` and `items.json`, foreign files excluded) ≤ 25,000,000 bytes (constant `TOTAL_BUDGET`, checked after writing, exit 1 when over; total printed).
11. **Clean-frame guards per scene (fail the scene, exit 1):** after `open`, the visible text (`document.body.innerText`) must contain no Cyrillic (`/[\u0400-\u04FF]/`), no "Loading" text and no e-mail other than `dev@example.com` (the check runs after the presentation-mode init script, which hides the top bar carrying the identity and rewrites every e-mail in the DOM to `dev@example.com`, so the real `LOGHUB_EMAIL` never reaches a frame); the mouse is parked at the bottom-right corner after every click. `master` fold as in the PoC (`capture.mjs:113-115`) runs before the check.

14. **Manifest `items.json`** (written by the script; read by the page and the scenario): array in catalog order of `{ id, kind: "tour"|"still"|"clip", src, still?, thumb, duration?, caption, where, alt }`; paths relative to the site root (`assets/demo/...`); `still` for GIFs only (the tour's is `assets/demo/app-tour.png`, a clip's `assets/demo/<id>.png`); `alt` = the tour alt text of Design Decision 22 for the tour, the caption otherwise; `duration` (ms) for GIFs only, computed by `gifDurationMs`. With `--only`, the script rewrites only the listed entries and keeps the others from the existing `items.json`.
15. **Carousel code location.** `site/assets/carousel.js` (vanilla IIFE in the style of `site/assets/site.js`, no dependency) loaded by `<script src="assets/carousel.js" defer>` inside the home section; rules appended to `site/assets/theme.css` (the layout `page()` in `scripts/site/layout.mjs:181-208` has one stylesheet and no per-page head slot).
16. **Item data loading.** `carousel.js` fetches `assets/demo/items.json` (relative, works under the base path) and then renders; until then the stage shows the loading placeholder. A failed fetch leaves the section with a one-line "Media unavailable" text, no JS error.
17. **Behaviour (from PoC `carousel.js:1-97`):** one media element on stage, thumbnails `loading="lazy"`, no preloading of the next/previous item's full media; timer starts on media `load`; still = constant `STILL_MS = 5000` ms, GIF = its `duration`; pause button toggles `aria-pressed`; `visibilitychange` re-schedules; ArrowLeft/Right on the focused carousel; pointer swipe (> 40 px, `touch-action: pan-y`); `prefers-reduced-motion` → starts paused and GIFs show their `still`. Thumbnail of a GIF carries a "▶ GIF" badge; the active thumbnail has `aria-current="true"` and is scrolled into view.
18. **Tap to open full size.** The stage media is wrapped in `<a class="mc-open" href="<src or still>" target="_blank" rel="noopener">`; a click that ended a swipe is cancelled. Same on desktop (harmless).
19. **Single item.** With fewer than 2 items the strip, prev/next and counter are hidden and autoplay is off.
20. **Frame token.** `theme.css` gets `--frame-bg: #fff` in `:root` and the same value in the dark override (the app background is white in both site themes); `.mc-stage` and `.mc-thumb` use `var(--frame-bg)` instead of the PoC's hard-coded `#fff`.
21. **Markup classes.** Section `<section class="media-section" aria-labelledby="media-title">` with `[data-mc]`; class names `mc-*` from the PoC (`preview.mjs:89-104`); never `cards`/`card` (S-SITE-01 step 3 counts exactly 3 `.cards .card`). Below 768 px (`@media (max-width: 767px)`, matching `theme.css:856`) the strip is hidden, the caption wraps, the counter stays.
22. **README placement.** After the line `[Deck](https://dataart.github.io/artisyn-log-hub/deck/)` and before the badges: a blank line, then `![Log Hub tour: repositories, sessions by cost, session summary, context growth, call tree, Session Map replay, change surface, cost by branch](site/assets/demo/app-tour.gif)`.
23. **Home alt text:** `carousel.js` sets each stage media `alt` from the item's `alt` field in `items.json` (Design Decision 14).

- `gifenc` ^1.0.3 (MIT, no deps) — GIF encoding, required by FR-6.

## Test coverage plan

Under the CLAUDE.md test policy only a **scenario** step applies — no algorithm doc covers this, no route changes, and the capture script is a manual tool with no test.

- **Scenario — extend `@S-SITE-01`** (`tests/scenarios/platform/s-site-01.spec.ts`, doc `docs/qaa-overview/scenarios/04-ingest-hook-installer-platform.md` §S-SITE-01) with step 19 "Home media carousel":
  - the built home has `.media-section [data-mc]` placed after `.hero`; `assets/demo/items.json` parses, has ≥ 30 items, item 1 is `kind: "tour"` with `src` `assets/demo/app-tour.gif`; every `src`/`still`/`thumb` answers 200 from the local server (the crawl does not see JSON paths);
  - `app-tour.gif` header: `GIF89a`, logical size 960×600 (bytes 6–9, little-endian), a `NETSCAPE2.0` block with loop count 0, file ≤ 5,000,000 bytes; frame-delay sum 22–28 s;
  - desktop 1440×900 first load: the `.gif`/`.png` requests under `assets/demo/` outside `thumbs/` equal exactly `[assets/demo/app-tour.gif]` (`items.json` and `thumbs/*.jpg` are not counted); counter reads `01 / NN`;
  - autoplay: click thumbnail 2 (a still), wait for its stage image to load, then `expect(counter).toHaveText('03 / NN', { timeout: 8000 })` and assert it did not change before 4.5 s; click pause, after 6 s it still reads `03 / NN`;
  - `reducedMotion: 'reduce'` context: pause button `aria-pressed="true"` and stage image `src` ends with `app-tour.png`;
  - 375 px: strip hidden, prev/next/pause and counter visible (no-horizontal-scroll is already step 7 over Home).
- `CONTENT_TYPES` gains `.gif` `image/gif` and `.jpg` `image/jpeg`; `test.setTimeout` goes from 240 s to 300 s.
- AC-2 (pixel content: no PII, non-English text, loading or hover state) is guarded by the script's clean-frame checks (Design Decision 11) and a human look at the outputs; it is not a scenario assertion.
